# Контракт зеркала: на что можно ссылаться и что считать дословным текстом

Одна страница для исполнителя Ф3 (статьи со сносками). До неё это знание
собиралось из четырёх докстрингов и двух отчётов; итоговое ревью Ф2 назвало
это главным пробелом документов — и было право: пока страницы не было,
дефект C2 (обещанный докстрингом якорь `## Запись`, которого в 528 заметках
не существовало) никто не заметил.

Все цифры ниже — замер на боевой базе `data/forum.sqlite` и готовой вики
`wiki/Источники` 21.08.2026, воспроизводится запросом рядом с цифрой.

## 1. Виды сносок: полный список, других нет

| Адрес | Что раскрывает | Сколько таких целей |
|---|---|---|
| `[[Тема <TID>]]` | тема целиком | 6338 (но см. §3 — пустых 2829) |
| `[[Тема <TID>#Пост <MID>]]` | один пост до следующего заголовка | 48 689 |
| `[[FAQ <N>]]` / `[[FAQ старый <N>]]` | запись FAQ целиком | 154 Bitrix + 20 старого движка |
| `[[FAQ <N>#Вопрос]]` | текст вопроса | 174 |
| `[[FAQ <N>#Ответ]]` | текст ответа | 174 |
| `[[Блог <слаг> <ID>]]` | запись блога целиком | 528 |
| `[[Блог <слаг> <ID>#Запись]]` | тело записи | 528 |
| `[[Блог <слаг> <ID>#Комментарий <N>]]` | один комментарий | 728 (у 113 записей) |

Чего в списке НЕТ и не будет: адреса «абзац поста» (блочные якоря `^p<MID>`
убраны в Ф2 — они адресовали последний абзац, а не пост), адреса «страница
темы» (`page_no` не является якорем) и адреса поста по «автор · дата»
(нестабильно, символы ников ломают ссылку Obsidian).

Имя заметки — функция ОДНОЙ записи, не корпуса: `Тема <TID>`, `FAQ <N>` /
`FAQ старый <N>` (движки — независимые пространства номеров, пересечений 17),
`Блог <слаг> <ID>` (номер уникален только внутри блога, пересечений 10).
Переименований не будет: названия живут в `aliases`, а не в имени файла.

Заголовок-адрес обязателен и защищён тестом `tests/test_anchor_contract.py`
— он проверяет и наличие полного набора заголовков у каждого генератора, и
то, что сноска указанного вида разрешается `check_mirror.check`. Меняешь
формат заголовка — тест падает; это не помеха, а смысл.

## 2. Канон дословной проверки — ТЕЛО ЗАМЕТКИ

Правило: **цитата в статье считается верной, если она дословно встречается
в теле заметки, на которую указывает сноска.** Не в поле базы.

Почему так (Ruling 30). У постов форума в базе три вида тела: `html`,
`markdown` (идёт в заметку) и `text` (плоский, по нему строится
полнотекстовый поиск `posts_fts`). `text` и `markdown` расходятся у **27 267
постов из 48 689 — 56 %**:

```sql
SELECT count(*) FROM posts WHERE text <> markdown;   -- 27267
```

Расхождение систематическое, а не шумовое: в `markdown` цитаты чужих слов
начинаются с `> `, ссылки выглядят как `[текст](адрес)`. Поэтому конвейер
«нашли фразу через FTS → вставили в статью → сверили с заметкой» дал бы
ложное «цитаты нет в источнике» больше чем в половине случаев. Заметки при
этом воспроизводятся байт-в-байт (полная пересборка в чистый каталог даёт
то же дерево) и физически являются целью сноски — значит они и есть истина.

Практический порядок работы Ф3:

1. **искать** — по плоскому тексту: `posts_fts` (форум), `faq_fts` (FAQ),
   `blog_fts` (записи блогов). Плоский текст — для поиска, и только;
2. **ссылаться** — на заметку и якорь из §1;
3. **сверять** — по телу заметки: `grep -F` по файлу, к которому ведёт
   сноска. Совпадение подстроки, без нормализации пробелов и без учёта
   `> `-префикса цитат: если цитируется чужая цитата внутри поста, в статью
   идёт текст вместе с тем видом, в котором он лежит в заметке.

Что НЕ является дословным источником:

- **`html`** — сырьё для пере-рендера, в вики не попадает вовсе;
- **`text`/`*_fts`** — поисковый индекс (см. 56 % выше);
- **выдержки блогов** — см. §4;
- **пометки об утрате картинок** (`(изображение не сохранилось: <адрес>)`,
  6267 штук в вики) — это текст ГЕНЕРАТОРА, не автора. В цитату он попасть
  не может по определению, но `grep`-ом ловится, и путать их нельзя.

## 3. Пустые и половинчатые заметки: на что ссылаться нельзя

**2829 из 6338 заметок форума не содержат ни одного поста** — в архив попало
оглавление темы, но не её страницы (`docs/coverage-notes.md`, группа
`missing`). Такая заметка несёт фронтматтер и коллаут «содержимое не
сохранилось». Ссылаться можно на **3509** заметок, не на 6338:

```sql
SELECT count(*) FROM threads t WHERE NOT EXISTS (SELECT 1 FROM posts p WHERE p.tid = t.tid);
```

**6 записей FAQ из 174 имеют пустой ответ** (`answer_md` пуст, в заметке
«(ответ не сохранился)»); на них тоже нельзя опираться как на источник.
Кроме того, из 174 записей уникального материала **~154**: 16
нормализованных вопросов встречаются в двух движках, и у 14 из 20 записей
старого движка ответ дословно содержится в битриксовом (Ruling 35).
Дедупликация — работа Ф3: иначе одна статья получит две сноски на «разные»
источники с одинаковым текстом.

Объём текста, который реально можно цитировать: форум `posts.markdown`
**15 746 933** знака, блоги `body_md` **991 474**, FAQ `answer_md`
**474 183**. Форум — 91 % корпуса.

## 4. Выдержки блогов: 56 записей, которые нельзя цитировать

У **56 из 528** записей блогов `is_excerpt = 1`: отдельной страницы записи
(`page=post`) в архиве нет, текст восстановлен из выдержки в ленте
(`page=blog`). У одной из них вдобавок `truncated = 1` — выдержка сама
обрезана меткой «Читать подробнее...».

В заметке это видно коллаутом `> [!warning] Запись не сохранилась отдельной
страницей — восстановлено по выдержке из ленты`, во фронтматтере —
`выдержка: true`.

Такая запись — свидетельство «такая запись была и была примерно о том-то»,
но **не дословный источник**: текст заведомо неполон, и цитата из него
может оказаться цитатой из ленты, а не из записи. Комментариев у выдержек
нет вовсе (лента их не показывает) — 728 комментариев принадлежат 113
записям, сохранившимся отдельной страницей.

## 5. Картинки

Вставка в заметке — `![[assets/<имя>]]`, относительный путь от каталога
заметки (`assets/` есть в каждом из трёх разделов зеркала). Имя файла —
`<sha1(нормализованный путь URL)[:16]><расширение>`: одна и та же картинка
получает одно и то же имя независимо от того, каким видом адреса (с `www.`,
с percent-encoding, с задвоенным слэшем) её вставили в текст.

Вставок в вики **1925**, файлов **1859** — расхождение штатное: один файл
может быть вставлен в несколько заметок. Разбивка вставок: форум 1525,
FAQ 105, блоги 295.

Картинки, которых нет, дают однострочную пометку из §2 — битой вставки в
вики нет ни одной (`run check` → `broken_embeds: 0`), это глобальное
ограничение фазы Ф2, и его нельзя ослаблять при добавлении статей.

## 6. Чем проверяется, что контракт соблюдён

```bash
python -m pipeline.run check                 # 0/0/0/0 по всей вики, включая статьи
python -m pipeline.run all --rebuild         # пересборка: дерево вики обязано совпасть побитово
.venv/bin/python -m pytest -q                # тесты, в т.ч. контракт якорей
```

`run check` проверяет всё дерево вики, а не только `Источники/`, — статьи
Ф3 попадают в тот же проход. Битая ссылка, битый якорь, задвоенный якорь и
битая вставка дают ненулевой код возврата.
