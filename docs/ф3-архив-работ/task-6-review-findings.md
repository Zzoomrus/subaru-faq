## Н1 (высокая) — закрытый список единиц пропускает больше, чем ловит; «тыс. км» — главная единица домена — не проверяется вовсе

`_UNITS_RAW` (`pipeline/verify.py:79`) содержит мм/см/км/кг/мл/атм/бар/нм/градус/дюйм + латиницу.
Любое число, за которым стоит НЕ эта единица, из проверки 5 выпадает целиком — не «проверяется
слабее», а не извлекается вообще.

**Живая подделка (ресурс втулок завышен в 4–5 раз, источник — реальная запись FAQ 82):**

```python
Q = ("втулки стоек стабилизаторов поперечной устойчивости, которые разбивается в среднем "
     "за 30-50 тыс. км. пробега")
run("K3", FM + "# Подвеска\n\nВтулки стоек ходят 130-150 тыс. км[^f1].\n"
    "\n## Сноски\n\n[^f1]: «%s» — [[FAQ 82#Ответ]]\n" % Q)     # -> ПРОШЛА
```

Цитата дословна, источник цитируем, подписи у FAQ нет и в статье нет — гейт говорит OK, а статья
утверждает «130–150 тыс. км» там, где источник говорит «30–50 тыс. км». Причина: после числа стоит
`тыс`, а не `км`.

**Вторая живая подделка (расход топлива уменьшен вдвое, источник — Тема 22328#Пост 160997):**

```python
run("A1", FM + "# Расход топлива Impreza\n\nВладельцы отмечают: расход в городе при спокойной езде "
    "всего 8,5 литра, а на трассе — 4,5 литра[^f1].\n"
    "\n## Сноски\n\n[^f1]: «Расход в городе при спокойной езде 13,5 литра на трассе - 8,5 литра»"
    " — Megavolt, 24.02.2009, [[Тема 22328#Пост 160997]]\n")   # -> ПРОШЛА
```

Та же ложь в единицах ИЗ списка (`мм`) ловится — то есть дело не в чём-то ещё, а ровно в списке.

**Замер на живом корпусе** (48 689 постов, `posts.markdown`), вхождений «число + единица»:

| в списке | | мимо списка | |
|---|---|---|---|
| км | 1 427 | л / литр(а/ов) | 1 683 |
| мм | 1 380 | тыс./тыщ/тысяч (пробег) | 1 516 |
| см | 412 | % | 1 039 |
| градус | 217 | л.с. | 383 |
| кг | 179 | В (вольт) | 254 |
| km | 172 | м (метр) | 171 |
| | | куб.см / см3 | 163 |
| | | А (ампер) | 153 |
| | | об/мин | 86 |
| | | дюймовая дробь с кавычкой (`3/16"`) | 68 |
| | | Нм / кгс·м | 44 |
| | | °C (знаком) | 36 |
| **итого ≈** | **3 787** | **итого ≈** | **5 596** |

Замер честный: `%` считался с исключением процент-кодирования URL (сырой `\d+\s?%` даёт 4 910,
из них 3 871 — куски вида `%D0` в ссылках; в таблице стоит очищенная цифра). Цены (`т.р`, `тыр` —
655 вхождений) в таблицу не включены: это не единица измерения.

То есть мимо проверки проходит примерно в полтора раза больше мест, где статья может подменить
цифру, чем через неё. Отчёт
называет список «сознательно консервативным» и это верно как решение, но **цена решения в отчёте
не измерена**, а инструкция ревью требовала именно замера. `тыс. км` — стандартная запись пробега
в этом домене; `л`/`литра` — объём масла и расход; `%` и `В` — электрика и антифриз. Это не
периферия домена, это его центр.

Смежное: дробь `3/16` проверяется только если за ней стоит слово-единица (`3/16 дюйма`).
Форма `3/16"` (68 вхождений в корпусе) не извлекается — `_SINGLE` требует единицу из списка,
кавычка в него не входит. Бриф требовал «дроби вида `3/16` сравниваются как строка целиком».

**Что делать.** Либо расширить список до реально встречающихся единиц (замер выше даёт готовый
перечень), либо перевернуть правило: проверять любое число, за которым идёт короткий токен, и
держать список ИСКЛЮЧЕНИЙ (год, руб, шт, месяцы) — тогда пропуск требует явного решения, а не
молчания. И в любом случае — печатать в отчёте `verify`, сколько чисел в статье осталось вне
проверки: сейчас «0 проблем» неотличимо от «ничего не проверялось».

## Н2 (высокая) — числа проверяются только в плоском абзаце: заголовок, список, таблица, коллаут и цитата ложь пропускают

`_sentences` (`pipeline/verify.py:145`) выбрасывает абзац целиком, если он начинается с `#` или
`>`, а внутри абзаца режет на предложения только по `.!?` — поэтому весь список и вся таблица
становятся ОДНИМ «предложением», и покрытие складывается по всем сноскам блока.

**Одна и та же ложь («выпускные ровно 4 мм» — сноска говорит про диапазон 2–4 мм у другого узла),
шесть раскладок:**

```python
run("C1-предложения", FM + "# Зазоры\n\nЗазор впускных клапанов 2 мм[^f1]. Зазор выпускных клапанов ровно 4 мм.\n" + SN)
run("C2-список",      FM + "# Зазоры\n\n- Зазор впускных клапанов 2 мм[^f1]\n- Зазор выпускных клапанов ровно 4 мм\n" + SN)
run("C3-таблица",     FM + "# Зазоры\n\n| Клапан | Зазор |\n|---|---|\n| впускной | 2 мм[^f1] |\n| выпускной | 4 мм |\n" + SN)
run("C4-заголовок",   FM + "# Зазоры\n\n## Зазор выпускных клапанов 4 мм\n\nЗазор впускных клапанов 2 мм[^f1].\n" + SN)
run("C5-коллаут",     FM + "# Зазоры\n\nЗазор впускных 2 мм[^f1].\n\n> [!warning] Зазор выпускных строго 4 мм, не больше 9 мм.\n" + SN)
run("C6-цитата",      FM + "# Зазоры\n\nЗазор впускных 2 мм[^f1].\n\n> По регламенту выпускные ставят на 9 мм.\n" + SN)
```

Результат: `C1` поймана, **`C2`–`C6` прошли**. Пять раскладок из шести — и это ровно те раскладки,
которыми техническая статья и записывает численные характеристики (таблица допусков, список
размеров, вывод в коллауте, цифра в подзаголовке). Проверка держится на том, что сегодняшние четыре
черновика написаны сплошной прозой; первая же таблица в статье снимает её без единой жалобы.

Отдельно: подделка `подменённое-число.md` написана именно в форме `C1` — единственной, которая
ловится. Корпус подделок не отличает «проверка работает» от «проверка работает на одной раскладке».

**Что делать.** Резать текст на утверждения независимо от разметки: пункт списка, ячейка таблицы,
строка заголовка и строка коллаута — самостоятельные единицы проверки, а не «не проза». Заодно
проверить: с покрытием, сложенным по блоку, ложь может опираться на сноску соседней строки, даже
если строки разнесены на десяток пунктов.

## Н3 (высокая) — определение сноски, спрятанное в кодблоке или комментарии, считается настоящим: читатель видит утверждение без источника, гейт говорит OK

`articles.used_ids` применяет `_strip_non_prose` (кодблок, инлайн-код, `<!-- -->`, `%%…%%`) —
маркер, спрятанный там, «использованным» не считается (это правили в задачах 3 и 5 трижды).
`_parse_footnote_definitions` в `verify.py` того же вычищения НЕ делает: определение, лежащее в
невидимом месте, попадает в `defs` как настоящее.

```python
DEF = ("[^f1]: «зазор между клапаном и коромыслоом варьируется в пределах 2 - 4 мм»"
       " — Shlans, 03.11.2007, [[Тема 25570#Пост 82650]]")
run("J1", FM + "# Зазоры\n\nЗазор клапанов 2 мм[^f1].\n\n## Сноски\n\n```\n" + DEF + "\n```\n")
run("J2", FM + "# Зазоры\n\nЗазор клапанов 2 мм[^f1].\n\n%%\n" + DEF + "\n%%\n")
run("J3", FM + "# Зазоры\n\nЗазор клапанов 2 мм[^f1].\n\n<!--\n" + DEF + "\n-->\n")
```

Все три **прошли**. В Obsidian ни одно из этих определений сноской не станет: `%%…%%` в режиме
чтения исчезает целиком, кодблок печатает текст буквально, HTML-комментарий не рендерится. Читатель
видит утверждение «зазор 2 мм» и рядом литерал `[^f1]`, ведущий никуда, — то есть **статья без
источника, объявленная проверенной**. Плюс определение в кодблоке даёт покрытие проверке чисел
(проверка 5) — невидимая сноска «подтверждает» цифру.

Асимметрия внутри одной проверки: одна её половина знает про `_strip_non_prose`, другая нет. Это тот
же класс расхождения, который Global Constraint №3 запрещает («два потребителя одного знания обязаны
ходить одной функцией»), только оба потребителя здесь — в одном модуле.

**Что делать.** Прогонять `articles._strip_non_prose` перед разбором определений (и перед поиском
чисел, см. Н7) — тогда обе половины проверки видят один и тот же текст.

## Н4 (средняя) — якорь ссылки в прозе не проверяется вовсе, хотя `check_mirror` умеет это делать

Проверка 2 (`pipeline/verify.py:198`) берёт из `check_mirror.LINK` только цель и **выбрасывает
якорь** (`for target, _anchor in ...`). Между тем `check_mirror.check` (тот самый модуль, которому
бриф велит доверить резолв) якорь сверяет и отдаёт отдельный список `broken_anchors` — с поддержкой
и заголовочного, и блочного вида.

```python
run("D1", FM + "# Зазоры\n\nЗазор 2 мм[^f1]. Разбор — [[Тема 25570#Пост 999999]].\n" + SN)   # ПРОШЛА
run("D2", FM + "# Зазоры\n\nЗазор 2 мм[^f1]. См. [[Тема 25570#Ответ]] и [[Тема 25570#^p82650]].\n" + SN)  # ПРОШЛА
run("D3", FM + "# Зазоры\n\nЗазор 2 мм[^f1]. Ещё см. [[Тема 3965#Пост 82650]].\n" + SN)      # ПРОШЛА
```

- `D1` — поста 999999 в теме нет;
- `D2` — якорь `#Ответ` в заметке ТЕМЫ не существует, а `#^p82650` — блочный якорь, который контракт
  зеркала (Global Constraint №2) объявил отменённым в Ф2, «их не существует»;
- `D3` — перекрёстная подмена: `mid` реальный, но из другой темы (в СНОСКЕ этот же трюк ловится,
  `D4` → «якорь отсутствует» — значит знание в проекте есть, до прозы оно просто не доходит).

Задание требует «ссылка резолвится через `check_mirror`» именно для того, чтобы «выдуманные и битые
ссылки» не проходили. Битая ссылка в прозе — половина этого класса, и она проходит.

**Что делать.** Либо звать `check_mirror.check` и фильтровать его находки по проверяемой статье,
либо перенести якорную ветку `check()._resolve`/`headings`/`blocks` в переиспользуемую функцию —
второй потребитель у неё уже есть, это и есть повод её выделить.

## Н5 (средняя) — ложное срабатывание на межстатейной ссылке: `verify` и `check_mirror.check` ходят по РАЗНЫМ деревьям

`run.py:652` зовёт `check_mirror.check(args.wiki)` — всё дерево вики, включая `wiki/Статьи/`.
`run.py:531` зовёт `verify.check(..., args.wiki / args.mirror_dir, ...)` — только
`wiki/Источники/`. Индекс заметок один и тот же по коду, но корни разные, поэтому один потребитель
считает ссылку целой, а другой — битой.

```python
run("D5", FM + "# Зазоры\n\nЗазор 2 мм[^f1]. См. также [[Расшифровка VIN Subaru]].\n" + SN)
# -> поймана: «ссылка [[Расшифровка VIN Subaru]] не резолвится ни в одну заметку зеркала»
```

Это находка не про подделку, а про шум: обычная перелинковка статей («см. также») будет
репортиться как выдуманная ссылка. Сейчас статья в вики одна, поэтому шума нет; со второй он
появится, а проверяльщик, дающий шум, отключают — это прямая формулировка задания.

Симметричная сторона того же корня: `check_mirror.check` увидит неоднозначность имён между
`Статьи/` и `Источники/`, а `verify` — нет.

**Что делать.** Резолвить по корню вики (`args.wiki`), а «источник сноски обязан лежать в
зеркале» проверять отдельным условием — по префиксу ключа, а не тем, что чужая часть дерева просто
не проиндексирована.

## Н6 (средняя) — проверка «источники, не процитированные ни разу» не является проверкой

`verify.check` возвращает `источники_без_цитаты` из frontmatter статьи
(`meta.get("неиспользованные_факты")`, `pipeline/verify.py:250`). Это поле пишет `articles.render` —
тот самый процесс, о котором докстринг модуля говорит: «исходит из того, что процесс мог быть
обойдён». Достаточно не написать строку — и мера показывает ноль.

```python
# та же статья, что и honest-контроль, но со снятой строкой frontmatter и снятым коллаутом
run("F4", "---\ntype: статья\nисточников: 2\nсобрано: 2026-08-22\n---\n\n# Зазоры\n\nЗазор 2 мм[^f1].\n" + SN)
# -> ПРОШЛА, источники_без_цитаты: []   (при том, что второй проверенный факт не использован)
```

Заодно не проверяется и `источников: N`: `run("F5", ...)` с `источников: 99` при одной сноске
проходит, хотя `verify` держит в руках `defs` и посчитать различные источники может в одну строку.
Задача 5 специально чинила завышение этого поля (F6/F6-бис) — гейт его не сторожит.

## Н7 (средняя) — шум на честной прозе: сокращения с точкой, маркер после точки, честный пересчёт единиц, числа в кодблоке и в комментарии

Все пять статей ниже **честные** — и все отвергнуты (инструкция ревью, пункт 4: «проверяльщик,
дающий шум, отключат»):

```python
run("I1", FM + "# Зазоры\n\nЗазор в пределах 2 мм, т. е. в норме[^f1].\n" + SN)
run("I2", FM + "# Зазоры\n\nЗазор в пределах 2 мм (см. обсуждение)[^f1].\n" + SN)
run("I3", FM + "# Зазоры\n\nЗазор в пределах 2 мм. [^f1]\n" + SN)
run("I4", FM + "# Зазоры\n\nЗазор 2 мм (0,2 см)[^f1].\n" + SN)
run("I5", FM + "# Зазоры\n\nЗазор 2 мм[^f1]. %%TODO: уточнить, не 9 мм ли%%\n" + SN)
run("I6", FM + "# Зазоры\n\nЗазор 2 мм[^f1].\n\n```\nболт M10 длиной 60 мм\n```\n" + SN)
```

Две причины:

1. `_SENT_SPLIT` (`(?<=[.!?])\s+`) не знает русских сокращений: «т. е.», «см.», «ок.», «стр.»
   рвут предложение, число остаётся без своей сноски. Диагностика при этом выдаёт обрубок
   («число «2 mm» в предложении «Зазор в пределах 2 мм, т.»»), по которому автор статьи не поймёт,
   что от него хотят. `I3` — тот же корень: маркер после точки уезжает в следующее предложение.
2. Числа ищутся в СЫРОМ тексте, а покрытие — в тексте, из которого `used_ids` вырезал кодблоки,
   инлайн-код и комментарии. `I5` жалуется на число внутри `%%…%%`, которого читатель не увидит
   никогда; `I6` — на число в примере кода. Это обратная сторона Н3: одна половина проверки видит
   не тот текст, что другая.

`I4` — отдельный сорт: честный пересчёт единиц автором статьи (2 мм = 0,2 см) объявляется
неподтверждённым числом. По букве брифа так и должно быть, но на живой техстатье это будет
встречаться, и решение стоит принять сознательно, а не обнаружить в первом же отчёте.

## Н8 (средняя) — обычная markdown-разметка вокруг числа отключает проверку

`_SINGLE` требует единицу сразу за числом (максимум один пробел), поэтому любой символ разметки
между ними снимает проверку. Ложь та же, что в Н2:

```python
run("G1", FM + "# Зазоры\n\nЗазор выпускных — **9** мм, впускных 2 мм[^f1].\n" + SN)   # ПРОШЛА
run("G2", FM + "# Зазоры\n\nЗазор выпускных — *9* мм, впускных 2 мм[^f1].\n" + SN)     # ПРОШЛА
run("G3", FM + "# Зазоры\n\nЗазор выпускных — **9 мм**, впускных 2 мм[^f1].\n" + SN)   # поймана
run("F1e", FM + "# Зазоры\n\nЗазор выпускных 9 *мм*, впускных 2 мм[^f1].\n" + SN)      # ПРОШЛА
```

Выделить цифру жирным — первое, что делают в технической статье; при этом «жирным всё выражение»
(`G3`) ловится, а «жирным только цифру» (`G1`) нет. Проверка ведёт себя непредсказуемо для автора.

Того же корня:

- невидимые разделители: `9​мм` (zero-width space) и `9⁠ мм` (word joiner) проходят,
  читатель видит «9 мм»; неразрывный пробел при этом работает штатно (`\s` его матчит) — то есть
  дыра именно в непробельных невидимках;
- диапазон с типографским тире: `run("H1", ... "Зазор клапанов 7–4 мм[^f1]." ...)` **проходит** —
  `_RANGE` требует ASCII-дефис, а `_SINGLE` подхватывает только второе число; первое (`7`) не
  проверяется вовсе. С ASCII-дефисом та же статья ловится;
- единица словом: `9 миллиметров` проходит (в списке только `мм`);
- число прописью («девять миллиметров») — проходит; это, вероятно, допустимая граница, но её стоит
  назвать в докстринге вместе с остальными, а не оставлять неявной.

**Что делать.** Снимать инлайн-разметку (`*`, `**`, `_`, `` ` ``) и невидимые символы перед поиском
чисел; в `_RANGE` добавить типографские тире (`–`, `—`, `−`) или, что надёжнее, извлекать все числа
абзаца и проверять каждое.

выдаёт индульгенцию всем числам сразу.

Живой источник (Тема 19033#Пост 160401) — четыре абзаца, четыре разных значения, каждое привязано к

```
вагон 270мм между болтом поперечного рычага и поверхностью эт впереди
сзади седан, 3-хдверное купе 265мм
```

Проза врёт: спереди у седана 266 мм, а 279 мм — это вагон сзади. Все четыре числа переставлены

## Н15 (высокая) — единицей считается любой короткий токен, и в исключениях нет предлогов, союзов и месяцев: честная проза отвергается

Правило «список исключений вместо списка разрешённого» верное, но список исключений собран из
существительных (год, руб, шт, раз, месяц, человек) и не содержит служебных слов. Единицей поэтому
становится любой предлог или союз после числа. Все шесть статей ниже **честные** и **отвергнуты**:

| случай | что видит проверяльщик | почему это шум |
|---|---|---|
| `в посте 104015 в теме про VIN` | число «104015 v» | **номер поста** — бриф прямо велел его НЕ проверять («число без единицы (номер поста, год) — не проверяется») |
| `Таблицу 13.02.2008 выложил участник` | число «02.2008 vylozhil» | дата разобрана как число, следующее слово — как единица |
| `Таблицу 13 февраля выложил` | число «13 fevralya» | названий месяцев в исключениях нет (есть только «месяц/месяца/месяцев») |
| `шли в 1992 и 1993 годах` | «1992 i» и «1993 godah» | союз как единица + падеж «годах» в списке отсутствует |
| `выпускалась с 1998 по 2002 год` | «1998 po» | предлог как единица |
| `У этой версии 4WD и механика` | «4 wd» | обозначение привода как число с единицей |

Первая строка — не просто шум, а **расхождение с брифом**: номер поста обязан не проверяться, а
проверяется. Остальные пять — обычная русская техническая проза; на пилоте они встретятся в первой
же статье про год выпуска или про то, кто и когда выложил таблицу.

Воспроизведение: `корпус.py` → `НОВЫЙ_ШУМ`, прогон печатает их группой «честная-2».

**Что делать.** Дополнить `_UNIT_EXCLUSIONS` служебными словами (предлоги, союзы, частицы —
закрытый класс языка, его можно перечислить целиком, в отличие от единиц), названиями месяцев и
остальными падежами «год»; отдельно запретить единицу после числа, которое само является датой
(`\d{2}\.\d{2}\.\d{4}`) или следует за `#`/«пост». Проверить по разбивке из п.2 замера — она

## Н16 (высокая) — величину можно спрятать за исключением: ложь про год выпуска не проверяется

Список исключений — сам по себе список, и он тоже обходится: число, за которым стоит исключённое
слово, не проверяется вовсе. Три подделки прошли:

```
Восьмой символ кодирует год: буква «С» означает 1998 год[^f1].     -> ПРОШЛА
   (источник: «8 - Год выпуска (С-1992)» — в статье 1998)
Ресурс втулок 5 лет, зазор 2 мм[^f1].                              -> ПРОШЛА
Выпускной зазор в 9 раза больше, зазор 2 мм[^f1].                  -> ПРОШЛА
```

Первая — не абстрактная: **год выпуска это ключевой факт домена** (8-й символ VIN), он стоит в уже
опубликованной статье вики, и подменить его можно безнаказанно. Формально бриф разрешает не
проверять «год», но он имел в виду год как СЛУЖЕБНОЕ число («1992 год» в дате поста), а не год как
утверждение статьи. Разница видна по позиции: год в сноске-цитате есть, значит его можно и нужно
сверять.

**Что делать.** Исключать не «число перед словом из списка», а «число, у которого нет единицы
измерения» — то есть считать `год`/`лет`/`раза` не единицей, но при этом проверять само число, если
оно встречается в цитате сноски этого утверждения. Тогда «1998 год» при цитате «(С-1992)» падает, а
«1992 год» проходит, и обходить исключение больше нечем.

## Н17 (средняя) — три списка разрешённого на уровень ниже: невидимые символы, разметка, составные единицы

Фикс закрыл ZWSP и WORD JOINER (`_INVISIBLE` — три символа) и `*`/`_` (`_EMPHASIS`). Но это опять
перечни, и мимо них проходит:

```
9­mм        (U+00AD soft hyphen)      -> ПРОШЛА
9‌мм        (U+200C zero width non-joiner) -> ПРОШЛА
==9== мм    (выделение Obsidian)      -> ПРОШЛА
~~9~~ мм    (зачёркивание)            -> ПРОШЛА
<b>9</b> мм (HTML, Obsidian рендерит) -> ПРОШЛА
9&nbsp;мм   (HTML-сущность)           -> ПРОШЛА
```

Все шесть читатель видит как «9 мм». `==…==` — родная разметка Obsidian, а `&nbsp;` и `<b>` в
Obsidian работают штатно, так что это не экзотика.

**Что делать.** Вместо перечня символов — снимать по классу: все символы категории Unicode `Cf`
(формат) плюс `U+00AD`; всю инлайн-разметку markdown/HTML одной зачисткой (`articles._strip_non_prose`
уже снимает кодблоки и комментарии — там же логично снимать теги и сущности); либо, что надёжнее,
сравнивать не «число, приклеенное к единице», а число и ближайшую единицу в пределах N символов.

### Пункты 4 и 5 задания ре-ревью (коммит `2117367a`)

**Пункт 4 — граница абзаца против вычищенных кусков: чисто, проверено массово.** Правило видит
границу так же, как её видит источник. Прогнал два инварианта по 6 000 секций живого зеркала:

```

  ложно признано межабзацными: 0   (в том числе 0 из тех, что с \x00)
ИНВАРИАНТ 2 — склейка двух СОСЕДНИХ абзацев должна считаться межабзацной
  верно распознано: 15 282

```

Ключевое: **цитата, задевающая вычищенный кусок, межабзацной по ошибке не считается** — 663 абзаца
содержат `\x00` (пометка об утрате картинки, шапка автора, блок чужого цитирования внутри абзаца), и
ни один не дал ложного «пересекает». Механика этому и не даёт сбиться: `citable()` заменяет

отбивает дословность (`needle in clean`), потому что `\x00` в цитате статьи взяться не может.

Единственное «пропущено» — вырожденный случай, не утечка: mid=320412, оба соседних абзаца целиком

Такая «цитата» не может существовать в статье вовсе (в тексте статьи нет NUL), значений в ней 0, и до
потолка дело не дойдёт. Реальных пропусков — ноль.

## Н19 (высокая, РЕГРЕСС — зарегистрирован ДО фикса) — класс служебных слов проглотил вольты, амперы и секунды

Пятая волна корпуса была заведена именно на этот случай, ещё до появления кода, и он произошёл:

```
_canon_unit("В") == 'v'  и  'v' ∈ _STRICT_EXCLUSIONS   (потому что предлог «в» → 'v')
напряжение 12 В  -> []      порог 0,1 В -> []      ток 5 А -> []      выдержка 3 с -> []
```

`_canon_unit` снимает регистр ДО проверки исключений, поэтому единица `В` (вольт) неотличима от
предлога `в`, `А` (ампер) — от союза `а`, `с` (секунда) — от предлога `с`. **Проверено, что это
именно регрессия:** на `2117367a` те же строки давали `('12','v')`, `('0.1','v')`, `('5','a')`,
`('3','s')`.

Следствие — подделка `П5-01` проходит: живой источник Тема 16109#Пост 104598 (Kolos, 15.02.2008)
говорит «если амплитуда сигнала < 0,1 В, то датчик неисправен», статья пишет «меньше 0,9 В» —
**порог диагностики завышен в 9 раз, гейт молчит.** Масштаб по живому корпусу: `В` заглавная — 162
вхождения в 103 постах, `А` — 113 в 79; это напряжения датчиков, аккумулятора и порогов
диагностики, то есть ровно те величины, из-за которых техбаза и нужна.

**Почему обратная проверка исполнителя этого не показала.** Он привёл довод «доля настоящих единиц
среди отсечённых выросла (15,1% → 26,6%), значит класс законные единицы не проглотил». Этот
инструмент такого проглатывания увидеть НЕ МОЖЕТ: единица, которая перестала извлекаться вовсе,
исчезает и из отсечённых тоже, и доля прочих настоящих от этого только растёт. Рост доли одинаково
объясняется и «шума стало меньше», и «часть настоящих выпала из проверки». Различить может только
подделка на конкретной единице — для этого пятая волна и заводилась заранее.

**Что делать.** Сверять служебное слово РЕГИСТРОЗАВИСИМО: исключать только строчную форму
(`в`, `а`, `с`), оставляя `В`, `А`, `С` единицами. Но одного регистра мало — заглавная буква
бывает и началом предложения (`Мест ровно 2. В цилиндре чисто`, случай `Ч5-02`), поэтому признак
должен быть составным: «токен в верхнем регистре И перед числом не стоит конца предложения».
Оба случая уже лежат в корпусе как подделка и как честный случай — фикс обязан развести их.

## Н20 (средняя, РЕГРЕСС контроля) — механизм Н16 требует источника для любого года и количества в прозе

`find_quantity_claims` возвращает голое число рядом с «мягким» существительным (год/лет/раз/шт/
месяц/человек/деньги), и `verify` требует найти это число в цитате сноски того же утверждения.
Лазейку Н16 это закрывает — но заодно делает проверяемым КАЖДЫЙ год и КАЖДОЕ количество в прозе,
включая упомянутые вскользь:

```
К-честная-08 (был зелёным все предыдущие круги):
  «Машина 1992 года, пост #104015, артикул 22611AD982 — двенадцатый символ кодирует коробку[^f1]»
  -> число «1992» ... не встречается ни в одной сноске этого утверждения
Ш2-04: «шли в 1992 и 1993 годах» -> число «1993» не найдено
Ш2-05: «выпускалась с 1998 по 2002 год» -> число «2002» не найдено
```

Бриф задачи прямо исключает этот класс: «число без единицы (номер поста, год) — **не
проверяется**: иначе шум затопит отчёт». Номер поста и дату исполнитель снял отдельными
структурными правилами (верно), а год и количество — наоборот, сделал проверяемыми. Решение
принято тимлидом сознательно ради Н16, и по существу оно право: год выпуска — факт домена. Но у
него есть цена, и её стоит назвать явно: **любой контекстный год в прозе теперь обязан быть в
цитате**, иначе статья не проходит. Для статьи, где год — это опорное утверждение, это правильно;
для фразы «машина 1992 года» как фона у утверждения про коробку — шум.

**Что делать (варианты, решать тимлиду).** Либо считать заявкой только год, стоящий в том же
сегменте, где есть сноска, И не встречающийся в прозе как часть даты/периода (сузить); либо
оставить как есть и явно записать в контракте, что контекстные годы надлежит подкреплять цитатой,
— тогда это требование к автору статьи, а не дефект. Сейчас это не записано нигде, и первым его
обнаружит пилот.

## Н15 (остаток, средняя) — четвёртая волна не тронута: русские порядковые, передачи, цилиндры, счётные существительные

## Н21 (высокая, БЛОКИРУЕТ) — литр съеден частицей «ль»: та же ловушка, где регистр не спасает

```
_canon_unit("ль") == _canon_unit("л") == 'l'     (транслитерация выбрасывает мягкий знак)
'l' ∈ _STRICT_EXCLUSIONS   ->   «масла 4,2 л» → []   «объём 5 л» → []   «расход 8,5 л» → []
```

Оба токена — частица `ль` и единица `л` — **строчные**, поэтому регистровое правило Н19 здесь
бессильно по построению. Проверил историю: на `2117367a` `«объём 5 л»` давало `('5','l')`; с
`824acee2` (коммит 35598034, класс служебных слов) — пусто, и правка Н19 этого не вернула.

Подделка `П6-01` проходит: живой источник Тема 22328#Пост 160997 (Megavolt) говорит «Расход в
городе при спокойной езде 13,5 литра на трассе - 8,5 литра», статья пишет «по городу выходит
8,5 л, по трассе 4,5 л» — **расход занижен вдвое, гейт молчит.** Полная форма «литра»/«литров»
работает, поэтому дыра ровно в сокращении — а сокращением на форуме и пишут: **«число + л» — 1 030
вхождений в 695 постах** (расход топлива, объём масла, ёмкость бака). Литр — вторая величина домена
после пробега.

Список всех столкновений единицы со служебным словом после транслитерации (проверено кодом):
`л`↔`ль` (**строчные оба — не лечится регистром**), `в`↔`в`, `а`↔`а`, `с`↔`с`, `к`↔`к` (последние
четыре регистром разведены или приняты как размен).

**И снова про метод проверки.** Довод «изменилось 601 написание, все 601 — только падение, ни
одного роста» этой дыры показать не может по той же причине, что и в прошлом круге: **съеденная
единица выглядит в точности как убранный артефакт** — падение и там, и там. Ни «все изменения —
падения», ни «доля настоящих выросла» не отличают одно от другого. Отличает только подделка на
конкретной единице; литр не был покрыт ни одной, поэтому и провалился молча. Шестая волна корпуса
эту страховку теперь ставит.

**Что делать.** Сверять исключения по СЫРОМУ строчному токену, а не по транслитерированному ключу:
транслитерация нужна, чтобы равнять `mm`==`мм`, и не должна быть ключом для теста на служебное
слово. Тогда `ль` перестанет совпадать с `л` без всяких перечней.

## Н22 (средняя) — неразрывный пробел внутри числа не канонизируется

`_NUM` принимает разрядным разделителем ` `, NBSP (U+00A0) и узкий (U+202F) — это правильно, — но
`_canon_number` снимает только ASCII-пробел. Поэтому `«10 000»` с NBSP канонизируется в
`'10 000'`, а цитата сноски всегда приведена `normalize_spaces` к обычному пробелу → ключи не
совпадут **никогда**:

```
find_number_units("пробег 10 000 км") -> [('10 000', 'km')]
find_number_units("пробег 10 000 км")      -> [('10000', 'km')]
```

Случай `Ч6-02` (честная статья с типографски правильным `130 000 км`) отвергается. Для русской
типографики NBSP внутри числа — норма, а не экзотика. Правка на одну строку: снимать в
`_canon_number` тот же набор разделителей, который принимает `_NUM`.

## БЛОКИРУЕТ — Н23: сокращение и полное слово одной единицы дают разные ключи

Честная статья на живом источнике отвергается. Источник (Тема 22328#Пост 160997, Megavolt)

```

     число «13.5 l» ... не встречается ни в одной сноске этого утверждения
     число «8.5 l»  ... не встречается ни в одной сноске этого утверждения
проза «По городу выходит 13,5 литра, на трассе 8,5 литра[^f1].» -> проходит
```

Разница между двумя статьями — ровно написание единицы: `л` против `литра`. Ключи `'l'` и
`'litra'` не равны, хотя величина одна.

**Это не регресс, а дефект, который вскрыла правка Н21:** пока `л` не извлекался вовсе, случай был
недостижим. Проверено на всех основных величинах — ни одна пара «сокращение / слово» не сходится:

| величина | сокращением | словом | ключи |
|---|---|---|---|
| литр | 1 033 | 650 | `l` ≠ `litra` |
| час | 15 | 274 | `ch` ≠ `chasa` |
| процент | 1 066 | 37 | `%` ≠ `procentov` |
| км | 1 465 | 23 | `km` ≠ `kilometrov` |
| мм | 1 446 | 8 | `mm` ≠ `millimetrov` |
| кг | 188 | 5 | `kg` ≠ `kilogramm` |

Опасны прежде всего **литр** (корпус пишет обоими способами почти вровну — расход топлива, объём
масла) и **час** (в корпусе преобладает слово, а проза статьи сократит). Проза статьи пишется ИИ по
проверенным фактам, и пересказать «13,5 литра» как «13,5 л» — самое естественное, что он сделает.

**Что делать.** Таблица синонимов единицы (`л`↔`литр/литра/литров`, `ч`↔`час*`, `%`↔`процент*`,
`км`↔`километр*`, `мм`↔`миллиметр*`, `кг`↔`килограмм*`, `В`↔`вольт`, `А`↔`ампер`). Это снова
перечень — но перечень **другой природы**, чем «список разрешённых единиц»: пропущенная строка
здесь даёт ЛОЖНОЕ СРАБАТЫВАНИЕ (громкое, видно сразу), а не молчаливый пропуск подделки. Это


Причина — несогласованность внутри одного составного вида: для «тыс.» единица за множителем
