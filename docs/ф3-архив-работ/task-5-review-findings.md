## F1 (критично). Запрет на самописную сноску обходится ОДНИМ ведущим пробелом

Главная защита задачи — «ИИ не может сам набрать определение сноски» — держится на
`_EMBEDDED_DEFINITION = re.compile(r"^\[\^[^\]]+\]:", re.M)` (`pipeline/articles.py:54`).
`^` требует нулевой отступ. Любой отступ (пробел, три пробела, табуляция) и обёртка
`> ` защиту снимают полностью.

**Воспроизведение — минимальное, без данных** (мой worktree удалён, повторяется в любом
дереве проекта):

```python
from pipeline import articles
V = [{"id":"f1","источник":"FAQ 100#Ответ","цитата":"это 4,75 мм","суть":"д"}]  # FAQ: подписи нет
for pre in ("", " ", "   ", "\t", "> "):                 # "" — колонка 0
    draft = "Диаметр[^f1].\n\n%s[^f1]: «это 4,75 мм» — ЧужойАвтор, 01.01.2000, [[FAQ 100#Ответ]]\n" % pre
    try:
        articles.render(draft, V, {"заголовок":"Х"}); print(repr(pre), "ПРОШЛО")
    except articles.DraftError: print(repr(pre), "отбито")
# '' отбито; ' ', '   ', '\t', '> ' — ПРОШЛО
```

**И на живых данных, через CLI** — так это и было найдено (в worktree с копией
`data/forum.sqlite`; я собирал статью по `FAQ 100#Ответ`, ключ `акпп-холод`):

```bash
printf '\n [^f1]: «пока рабочая жидкость автоматической коробки передач не достигнет определенной температуры» — ЧужойАвтор, 01.01.2000, [[FAQ 100#Ответ]]\n' \
  >> "articles/черновики/акпп-холод.md"          # один ведущий пробел
python -m pipeline.run article --key акпп-холод --root .
# статья собрана: wiki/Статьи/АКПП/АКПП Subaru на холоде.md   (exit=0)
python -m pipeline.run check --wiki wiki
# целостность: {'broken_links': 0, 'broken_anchors': 0, 'duplicate_anchors': 0, 'broken_embeds': 0}
```

Тот же черновик БЕЗ пробела отбивается штатно (`ОШИБКА: черновик содержит готовое
определение сноски «[^f1]:»`, exit=2) — то есть тест
`test_ai_cannot_fake_a_footnote_by_typing_its_own_definition` проверяет ровно ту
единственную форму, которую и так никто не станет использовать, если хочет пройти.

Прошли все проверенные варианты (`articles.render` напрямую):

| форма | результат |
|---|---|
| `[^f1]: …` в колонке 0 | **отбито** (единственный отбитый случай) |
| ` [^f1]: …` (1 пробел) | прошло |
| `   [^f1]: …` (3 пробела) | прошло |
| `\t[^f1]: …` | прошло |
| `> [^f1]: …` (в цитате) | прошло |
| CRLF-черновик, 1 пробел | прошло |

**Почему это худший из возможных случаев именно на FAQ.** Код по контракту рендерит
для FAQ сноску БЕЗ подписи (`— [[FAQ 100#Ответ]]`), потому что автора-человека и
настоящей даты у записи нет. Протащенная строка выдумывает и автора, и дату — то
самое, чего весь проект избегает. В собранной статье обе строки стоят рядом:

```
 [^f1]: «пока рабочая жидкость …» — ЧужойАвтор, 01.01.2000, [[FAQ 100#Ответ]]
…
[^f1]: «пока рабочая жидкость … и гидротрансформатор не блокируется» — [[FAQ 100#Ответ]]
```

Два вреда, и второй не зависит ни от какого парсера:

1. **Возможный захват определения.** В файле теперь ДВА определения `[^f1]:`.
   Парсеры сносок обычно берут первое; подделка стоит выше кода. Точное поведение
   Obsidian здесь не проверялось (рендер в этой среде недоступен) — не утверждаю, что
   захват гарантирован, утверждаю, что он возможен и ничем не запрещён.
2. **Гарантированно:** в теле статьи появляется строка, визуально неотличимая от
   сноски, с выдуманной подписью под настоящей дословной цитатой. Читателю она видна
   при любом парсере. `run check` её не видит — ссылка-то настоящая.

**Починка — ВАЖНО, моё первое предложение было недостаточным.** Прогнал корпус из 20
форм префикса (`task-5-rereview/атака-f1.py`) против трёх вариантов регулярки:

| вариант | пропускает |
|---|---|
| `^[ \t>]*\[\^…\]:` (то, что я предложил сначала) | **13 из 20**: `- `, `* `, `+ `, `1. `, `> - `, NBSP, U+202F, U+200B, U+3000, `\v`, `\f`, `•\xa0` |
| `^\s*\[\^…\]:` (юникодный пробел) | **11 из 20**: все `>`-формы, все списочные, U+200B |
| **`\[\^[^\]\s]+\]:` — БЕЗ якоря `^`** | **0 из 20 — закрывает всё** |

Рекомендую последний. Смысл: у последовательности «маркер, сразу двоеточие» нет ни
одного законного применения в прозе прохода 2 — ИИ обязан ставить голый `[^f1]`, и
только код имеет право поставить после маркера двоеточие. Пока в регулярке есть якорь
`^`, её обход — это вопрос фантазии на префикс (пробел, список, цитата, юникодный
пробел, маркер списка внутри цитаты), и перечислить все формы заранее нельзя.
Убрав якорь, перечислять не нужно. Ложных срабатываний на законной прозе не нашёл
(проверил 7 образцов: маркеры в тексте, в заголовке, рядом с `[[ссылкой]]`, время
«12:30», двоеточие после обычного слова — всё проходит); единственное срабатывание —
`Сноска[^f1]: так писать нельзя`, то есть ровно то, что и должно быть запрещено.

Тест нужен на КАЖДУЮ строку корпуса, а не на одну форму: сейчас все 20 покрыты одним
тестом на ту единственную, которая и так отбивалась.

## F2 (высокая). Многострочная цитата разрывает сноску — подпись и ссылка вылетают в тело

Дословность цитаты по канону фазы сверяется через `notes.normalize_spaces` (перенос
строки в заметке не подделка, Global Constraint №1). Значит цитата, законно прошедшая
проход 1, МОЖЕТ содержать `\n`. `_footnote_line` подставляет её сырой — и вторая
строка вываливается из определения сноски вместе с подписью и ссылкой.

**Воспроизведение (end-to-end, `facts` → `render`):**

```python
# пост в заметке: "Трубки нужны 3/16 дюйма,\nэто 4,75 мм."
f = {"источник":"Тема 1#Пост 100","цитата":"Трубки нужны 3/16 дюйма,\nэто 4,75 мм","суть":"диаметр"}
facts.check_one(f, root)      # -> (True, '')   ← гейт пропускает по канону, и правильно
articles.render("Диаметр трубки[^f1].", facts.check_all([f], root)["проверено"], {...})
```

Результат:

```
[^f1]: «Трубки нужны 3/16 дюйма,
это 4,75 мм» — Razum, 11.10.2014, [[Тема 1#Пост 100]]
```

Сноска обрывается на первой строке; **автор, дата и ссылка оказываются вне сноски** —
то есть ровно та привязка утверждения к источнику, ради которой существует модуль,
для этого факта разрушена. Не атака, а обычные данные: посты форума многострочные,
и цитата через перенос — штатный, разрешённый случай.

**Починка:** `quote = notes.normalize_spaces(fact.get("цитата", ""))` — той же
функцией, что уже канонизирует пробелы у двух других потребителей (Global Constraint
№3: своей копии правила не заводить). Заодно снимает риск, что в цитате приедет `\r`.

## F3 (высокая). `путь` и `заголовок` из черновика ИИ пишут файл куда угодно

`build` подставляет оба поля в путь без нормализации
(`pipeline/articles.py:228-230`). Черновик пишет ИИ прохода 2.

```python
# путь: ../../../../tmp/sf-escape        -> /tmp/sf-escape/Взлом.md            (файл создан)
# путь: /tmp/sf-escape-abs (абсолютный)  -> /tmp/sf-escape-abs/Х.md            (файл создан)
# заголовок: ../../../../tmp/x           -> FileNotFoundError (падение, не DraftError)
# заголовок: Ремонт EJ20/EJ25            -> FileNotFoundError (падение, не DraftError)
```

Первые два — запись вне `wiki/Статьи` без единой жалобы. Абсолютный путь особенно
неприятен: `Path("wiki/Статьи") / "/tmp/x"` в pathlib молча ОТБРАСЫВАЕТ левую часть.

Последний случай — не атака, а вероятная жизнь: слэш в заголовке статьи про Subaru
(«EJ20/EJ25», «АКПП/МКПП», «3/16 дюйма») напрашивается сам, и вместо внятного
`DraftError` исполнитель получит `FileNotFoundError` с длинным путём внутри. Это тот
же класс «молчаливой неверной папки», против которого исполнитель совершенно правильно
потребовал явный `путь` (см. оценку решений ниже) — защита поставлена от угадывания,
но не от подстановки.

**Починка:** проверить `resolve()` результата на принадлежность `<root>/wiki/Статьи`
и отбить `DraftError`, если вышли за пределы или если в `заголовок`/`путь` есть `/`,
`\`, `..` — рядом с уже существующей проверкой обязательности `путь`.

## F4 (средняя). Маркер в блоке кода и в HTML-комментарии считается «использованным»

`used_ids` сканирует сырой текст без понятия о разметке. Проверено:

```python
draft = ("Полностью недоказанное утверждение: масло менять раз в 5 тыс. км.\n\n"
         "<!-- [^f1] -->\n\n```\n[^f2]\n```\n\nи `[^f3]` в инлайн-коде.\n")
articles.used_ids(draft)                       # -> ['f1', 'f2', 'f3']
"неиспользованные_факты" in articles.render(...)  # -> False
```

Проза не подкреплена ничем, все три факта числятся процитированными, поле
`неиспользованные_факты` пусто. Доля непроцитированного — заявленный измеряемый
результат фазы (спека §6); маркер в HTML-комментарии в отрендеренном виде невидим
вообще, то есть замер обнуляется, а статья выглядит полностью «со ссылками».
Побочно: сноска `[^f1]` рендерится, а ссылки на неё в видимом тексте нет.

Отмечу честно: это требует намеренного действия ИИ и не подделывает подпись —
поэтому «средняя», а не «высокая». Но именно этот пункт бригадир просил проверить
отдельно, и он не закрыт.

**Починка:** перед `used_ids` вырезать fenced/inline-код и HTML-комментарии, либо
хотя бы отдельно сообщать «маркеры, найденные в коде/комментариях» — молчать нельзя
по той же логике, по которой не молчат про неиспользованный факт.

## F5 (средняя). `собрано: date.today()` — пересборка не побитовая (Global Constraint №8)

`render` при отсутствии `собрано` в черновике ставит текущую дату
(`pipeline/articles.py:142`). Живой черновик `расшифровка-вин.md` поля `собрано` **не
несёт** (`grep -c собрано` → 0), то есть боевой путь — именно недетерминированный.

```python
articles.render(d, V, {"заголовок":"Х"}) == articles.render(d, V, {"заголовок":"Х","собрано":"2026-08-21"})
# False — различаются строкой `собрано:`
```

Пересборка той же статьи завтра даст другой файл: `diff -rq` покажет расхождение,
`git status` — грязь. Constraint №8 делает побитовую пересборку условием сдачи любой
задачи, меняющей генераторы; в отчёте проверка побитовости для `article` не заявлена.

**Важный нюанс, почему это могло пройти незамеченным:** в пределах ОДНИХ суток
пересборка побитово идентична — проверил, три статьи пересобрались байт в байт.
Расхождение появляется только при смене суток. То есть обычная проверка «собрал →
пересобрал → `diff` пуст», сделанная в один день, эту дыру НЕ ловит; ловит её только
подстановка даты или сборка на следующий день. Проверять надо не `diff` после
пересборки, а отсутствие `date.today()` в генераторе.

**Починка:** брать дату только из `meta` (и требовать её, как `путь`), либо из mtime
черновика — что угодно, чей источник не «сейчас».

## F9 (низкая, к сведению). Нераспознанный маркер молчит

`[^f1 ]` и `[^ f1]` под `_MARKER` не подходят: маркера нет вовсе, факт становится
«неиспользованным», а в прозе остаётся литеральный текст. Поведение безопасное
(fail-closed, видно в статье), но диагностики «похоже на маркер, но не маркер» нет.
Похожие идентификаторы отбиваются как надо: `[^f10]`, `[^F1]`, `[^f01]` и маркер с
нулевой шириной внутри — все дают `DraftError` (проверено).

## F10 (низкая). `узел`/`модель` идут во frontmatter без экранирования

## Что проверено и нарушений НЕ найдено

1. **Два вида сноски — честны.** Собрал своей рукой статью на FAQ (`FAQ 100#Ответ`,
   у записи нет ни автора, ни настоящей даты) — вышло `[^f1]: «…» — [[FAQ 100#Ответ]]`,
   без подписи и **без всякой заглушки**. Мутация «подставлять „автор неизвестен“
   вместо пустой подписи» валит ровно те два теста, которые это и охраняют. Частичная
   атрибуция (автор есть, даты нет) даёт осмысленное `— Основатель, [[Тема 1#Пост 1]]`.
   Проверил и блог с комментариями: `Комментарий 398 → Spike, 02.11.2010`,
   `Комментарий 399 → GrandWagon, 03.11.2010` — сверено глазами с заметкой, подписи
   верные, у записи блога — свой автор и своя дата.
2. **Неиспользованный факт виден в ГОТОВОЙ статье**, не только в юнит-тесте. В моей
   статье «АКПП Subaru на холоде» f4 не процитирован — в файле есть и
   `неиспользованные_факты: [f4]` во frontmatter, и `> [!warning] Факты не
   использованы: f4` в теле. (Оговорки — F4 и F7.)
3. **Второй копии знания нет.** `articles.py` не резолвит имён заметок и не считает
   путей к вложениям вовсе: в модуле нет ни `check_mirror`, ни `mirror_assets_dir`, ни
   glob по зеркалу — только два своих входных пути и один выходной, что и есть его
   контракт. Резолв живёт в `facts.check_one` → `check_mirror.build_notes_index/
   resolve_note` (проход 1). Global Constraint №3 соблюдён — и соблюдён правильным
   способом: не «второй раз той же функцией», а «одним разом на проходе 1».

| форма | проходит guard | создаёт настоящую сноску |
|---|---|---|
| ZWSP U+200B между `]` и `:` | да | нет |
| word-joiner U+2060 | да | нет |
| HTML-сущность `&#58;` | да | нет |
| полноширинное `：` U+FF1A | да | нет |
| модификатор `꞉` U+A789 | да | нет |

(вред «а» из F1) закрыт полностью. Остаётся вред «б»: строка, визуально неотличимая от
сноски, с выдуманной подписью (ZWSP и `&#58;` в отрендеренном виде дают ровно
`[^f1]: «цитата» — ЧужойАвтор, 01.01.2000`).

Регуляркой по черновику этот класс не закрывается в принципе: проза — свободный текст,
и ИИ может просто написать в предложении «как писал Иванов 01.01.2000». Поэтому считаю
это не заявкой на фикс, а **подтверждением уже принятого решения**: подпись обязан
независимо сверять с базой `verify.py` задачи 6. Одна защита на форме, вторая на
