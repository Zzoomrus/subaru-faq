## Интерфейс передачи базы (для журнала — как просили)

```python
facts.check_all(facts: list[dict], mirror_root: Path, conn: sqlite3.Connection | None = None) -> dict
```

`conn` — необязательный третий параметр, а не обязательный: тесты и программные вызовы без
базы под рукой продолжают работать как в брифе (ключи `автор`/`дата` у прошедших фактов
просто не добавляются, а не становятся `None` незапрошенно). CLI-команда `facts`, наоборот,
**требует** существующую `--db` и отказывает кодом 2, если её нет — молчаливая проверка без
атрибуции была бы обнаружена только при рендере сноски в задаче 5, а не сразу.

`check_one`/`check_one`-цепочка `conn` не получает вовсе — резолюция и дословная проверка не
знают о базе ничего, атрибуция целиком относится к `check_all`. Разделение осознанное:
верификация цитаты и приписывание авторства — разные обязанности, первая не должна становиться
сложнее ради второй.

### Откуда берутся автор/дата по видам сносок (`docs/контракт-зеркала.md` §1)

| Вид источника | Автор/дата |
|---|---|
| `Тема <T>#Пост <M>` | `posts.author`/`posted_at` по `mid` |
| `Тема <T>` (без якоря, сноска на тему целиком) | фолбэк на `threads.author`/`started_at` (первое сообщение темы; заполнено у 4726 тем из 6338 — иначе `(None, None)`, это не ошибка) |
| `Блог <слаг> <N>#Запись` / `Блог <слаг> <N>` | `blog_posts.author`/`posted_at` |
| `Блог <слаг> <N>#Комментарий <K>` | `blog_comments.author`/`posted_at` — у комментария СВОИ автор/дата, не записи |
| `FAQ <N>#Вопрос` / `#Ответ` / целиком, любой движок | **всегда `(None, None)`** |

**FAQ — решение, которое нужно донести до задачи 5.** У таблицы `faq` нет колонки автора
вовсе — это база знаний, а не форумная реплика. Единственное временное поле — `snapshot_ts`,
и это дата, когда запись СНЯЛ краулер, а не когда её написали. Подставить `snapshot_ts` в
«дату» сноски значило бы приписать записи чужую (архивную) дату как будто авторскую — обман
того же семейства, для защиты от которого механически проверяется дословность цитаты. Поэтому
FAQ-факты всегда проходят гейт (если цитата дословна) с `автор=None, дата=None`. Формат сноски
задачи 5 (`«цитата» — Razum, 11.10.2014, [[...]]`) в текущем виде подразумевает оба поля
всегда — для источников FAQ ей понадобится отдельная ветка рендера (без подписи, или другая
формулировка).

Даты нормализуются к `DD.MM.YYYY` функцией `_only_date` — она НЕ переиспользует `mirror._ru_dt`
(та собирает дату+время для шапки поста в заметке и не понимает один из двух реальных сырых
форматов): в базе даты лежат в двух разных видах — ISO у форума/тем (`2014-10-11 12:00:00`,
`2014-10-11`) и уже русский с временем у блогов (`09.08.2011 10:41:53`, так его отформатировал
парсер задачи 7 Ф2). Проверено на реальных строках из `data/forum.sqlite`, покрыто отдельными
unit-тестами на все три формы плюс `None`/пустую строку.

**Найден живой гап гейта, не мой мандат чинить (по твоей инструкции), но нужно решение.**
Пустая тема форума (`Тема 143`, раздел 6 — просто первая попавшаяся, таких 2829 из 6338)
несёт в теле заметки коллаут генератора:

```
> [!missing] содержимое не сохранилось
```

Это текст ГЕНЕРАТОРА (`pipeline/mirror.py:461`, литерал внутри `_missing_note`/соседнего кода
записи пустых тем), но он НЕ входит в `notes.citable`'s `GENERATOR_PATTERNS` — тот реестр
собран под ДРУГОЙ класс плейсхолдеров (утрата картинки, пустой FAQ/blog-текст, шапка
автор·дата, вставка файла), а не под маркер «у темы вообще нет постов». Проверил вживую:

```python
facts.check_one({"источник": "Тема 143", "цитата": "содержимое не сохранилось", "суть": "тема пуста"}, mirror)
# -> (True, '')
```

Факт **проходит гейт**, хотя цитирует не автора, а код генератора — ровно тот класс обмана,
для защиты от которого гейт существует. По счастью, единственный способ получить такой
источник — сослаться на пустую тему целиком БЕЗ якоря поста (у пустой темы нет ни одного
`##### Пост`, так что якорный путь автоматически отказывает по «якорь отсутствует»), а пустые
темы — это ровно исключаемый задачей 6 класс источников (Global Constraint №5). Не чинил сам:
это работа проверяльщика задачи 6, а фикс здесь так или иначе трогает либо `notes.citable`
(генераторный реестр, GC8 — «полная пересборка обязана оставаться побитовой», лишний повод для
диффа) либо вводит в `facts.py` метаданную проверку «в теме есть хоть один пост», которая по
сути дублирует будущую работу задачи 6. Решаю за тебя, как поступить:
- дёшево закрыть здесь точечно (в `check_one` отказывать, если у резолвленной заметки нет ни
  одного заголовка `##### Пост` совсем — специфично для формы «сноска без якоря»), или
- оставить как есть до задачи 6, зафиксировав в её брифе явно.

**Обновление после ревью: закрыт как побочный эффект Н2.** Единственный способ процитировать
пустую тему был через сноску БЕЗ якоря поста (у пустой темы нет ни одного `##### Пост`) — Н2
теперь отвергает ЛЮБУЮ цитату без точного якоря безусловно, до какой-либо проверки содержимого.
Проверено вживую: `facts.check_one({"источник": "Тема 143", "цитата": "содержимое не
