## Что сделано

`pipeline/notes.py` + `tests/test_notes.py` — код и тесты взяты из брифа
буквально, без отступлений:

- `notes.body(path)` — текст заметки без frontmatter (`---\n...\n---\n`
  срезается один раз в начале файла).
- `notes.section(path, anchor)` — текст от заголовка `anchor` до следующего
  заголовка **любого уровня** (`HEADING = ^(#{1,6})\s+(.+?)\s*$`, `re.M`),
  `None` если заголовка с таким текстом нет.
- `notes.citable(text)` — прогоняет текст через `GENERATOR_PATTERNS`
  (замена на пробел): пометка об утрате картинки, плейсхолдеры
  `(пустой комментарий)`/`(пусто)`, шапка «*Автор · дата · #N*», вставка
  `![[...]]`.
- `notes.GENERATOR_PATTERNS` — публичный тьюпл этих regex, как требует
  интерфейс.

### Изменения

1. **Источник истины — сами генераторы.** `mirror.py` (`IMAGE_LOST_
   TEMPLATE`), `mirror_faq.py` (`QUESTION_LOST`, `ANSWER_LOST`),
   `mirror_blog.py` (`EMPTY_COMMENT`, `BODY_LOST`, `REPLY_MARKER_TEMPLATE`)
   теперь экспортируют плейсхолдеры именованными константами; сами
   генераторы вставляют их же (переименование литерала в константу,
   значение не изменилось — подтверждено побитовой пересборкой ниже).
2. **`notes.GENERATOR_PATTERNS` собирается ИЗ этих констант**, а не
   дублирует текст: `_exact_line(literal)` — для плейсхолдера, который
   всегда занимает целую строку-абзац; `_templated(template, "%s"/"%d",
   wildcard)` — экранирует неизменные куски шаблона и подставляет
   wildcard на месте переменной, регэксп собирается программно, а не
   переписывается руками.
3. **Контрактный тест** (`test_every_generator_placeholder_literal_is_
   scrubbed_by_citable`, по образцу `test_anchor_contract.py`): AST-обход
   трёх модулей-генераторов находит все строковые константы формы
   `(...)`/`*(...)*` и проверяет, что `citable()` вычищает неизменные
   куски каждой. Не перечисление руками — механическая проверка по факту
   написанного в генераторах.
4. **Шапка поста/комментария матчится структурой**: `^\*.+? · \d{2}\.
   \d{2}\.\d{4}.*?\*$` вместо `^\*[^*\n]+ · ...[^*\n]*\*$` — дата якорит
   правую границу, звёздочка в нике (цензура форума) больше не мешает
   распознаванию.
5. **`body()`**: `text.find("\n---\n", 0)` вместо `text.find("\n---\n",
   4)` — старт поиска с 0 не создаёт ложного совпадения с открывающим
   `---` (искомая подстрока начинается с `\n`, а перед позицией 0 файла
   `\n` нет), но теперь видит закрывающий разделитель вырожденного
   пустого frontmatter.

## Вторая доделка ревью: контракт по результату, а не по исходнику

Ревьюер независимо подтвердил ноль нечищенных фрагментов, отсутствие
порчи авторского текста и точность шапки (49417 совпадений = 48689
постов + 728 комментариев). Но нашёл слепую зону контрактного теста:
AST-скан ищет ЦЕЛЬНЫЙ литеральный узел `(...)`/`*(...)*` — если новый
плейсхолдер в генераторе записан f-строкой или конкатенацией, ни один
кусок такого выражения не является одним `ast.Constant`, совпадающим с
формой целиком, и скан проходит молча. Смысл контракта — поймать ЧУЖУЮ
будущую правку произвольной формы, значит форма записи не должна иметь
значения вовсе.

**Фикс** (коммит `85414175`, только `tests/test_notes.py`):
`test_every_generator_placeholder_constant_value_is_scrubbed_by_citable`
— новый главный рубеж. Берёт не текст исходника, а РЕЗУЛЬТАТ: `vars(module)`
после импорта, все заглавные строковые константы (ровно 6 известных,
без ложных срабатываний — проверено), и гоняет их значения через
`citable()`. Литерал/f-строка/конкатенация после импорта — обычный
`str`, для этой проверки неотличимы. Старый AST-скан оставлен вторым
рубежом (ловит константу, объявленную, но забытую использовать).

**Доказательство всеми тремя формами** (впрыск в `mirror_blog.py`,
копия `/tmp/mirror_blog_good3.py` для восстановления, `diff` = 0 после
каждой):

| Форма | `test_every_generator_placeholder_literal_...` (старый, AST) | `test_every_generator_placeholder_constant_value_...` (новый) |

| `LEAK_FSTRING = f"(вложение удалено {word})"` | **проходит молча** (воспроизвёл находку ревьюера) | ПАДАЕТ |
| `LEAK_CONCAT = "(вложение удалено " + "модератором)"` | **проходит молча** | ПАДАЕТ |

## Третья доделка ревью: плейсхолдер обязан быть модульной константой

Ре-ревью подтвердило фикс доделки №2 всеми тремя формами. Нашлась
четвёртая, ортогональная слепая зона: **инлайновая f-строка/конкатенация
прямо в месте использования, без подъёма в модульную константу** —
ревьюер вписал такую в `mirror_blog.py`, и она прошла мимо ОБОИХ рубежей
молча. Причина точная: значение-based тест смотрит только `vars(module)`
после импорта — локальное выражение внутри тела функции туда никогда не
попадает; AST-по-литералу видит только цельный `ast.Constant` — тип узла
другой независимо от места. Лид отказался фиксировать это известным
ограничением (цена промаха та же — незамеченный плейсхолдер станет
цитируемым) и попросил закрыть проверяемой конвенцией «плейсхолдер
обязан быть модульной константой».

**Фикс** (коммит `50eab84e`, только `tests/test_notes.py`):
`test_dynamic_placeholder_shaped_strings_must_be_module_constants` —
третий рубеж. AST-обход находит f-строки/конкатенации ГДЕ УГОДНО в трёх
генераторах; `_string_literal_skeleton` восстанавливает силуэт выражения
(литеральные куски как есть, место интерполяции f-строки — `\0`), причём
если силуэт нельзя восстановить целиком статически (внутри выражения
встретился вызов функции или имя переменной — например существующие
`"\n".join(out).rstrip("\n") + "\n"` в `mirror.py`/`mirror_blog.py`),
выражение не флагуется вовсе — не гадать, а не подставлять безопасное
предположение, ровно принцип `_templated` в `notes.py`. Если силуэт похож
