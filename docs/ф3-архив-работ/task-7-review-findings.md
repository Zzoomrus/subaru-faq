### 1 [Средняя, на решение лида] Форумная нога знаменателя не исключает «немые» темы — аналог «из одних картинок», которого нет для форума

Контракт (`docs/контракт-зеркала.md` §3) исключает из цитируемых: пустые темы форума
(0 постов), выдержки блогов, дубли FAQ, записи FAQ/блогов из одних картинок. Для форума
аналога «из одних картинок» в исключениях **нет вообще** — `citable_sources()` включает
в знаменатель ЛЮБУЮ тему с ≥1 постом, независимо от того, есть ли в этих постах хоть
что-то физически цитируемое (≥`MIN_QUOTE_CHARS=8` символов после `notes.citable()`,
жёсткий гейт в `facts.check_one`).

Проверил прямым скриптом по `notes.citable()` + `normalize_spaces` на каждом посте каждой
из 3509 тем «с постами»: **23 темы**, где ни один пост не даёт ≥8 «чистых» символов —
т.е. ни для одной из них физически невозможно построить проверяемую цитату (структурно
то же самое, что «из одних картинок» у FAQ/блогов). Примеры живого содержимого:

```
Тема 27492: посты "test", "test"
Тема 28482: пост "...."
Тема 37939: пост "ф"
Тема 34497: пост "летние"
```

23 из 4100 (~0,56%) — на текущем пилоте (1 статья, 1 цитата) итоговую долю 0,9998
практически не меняет, но именно это ЧИСЛО (не строка отчёта) уйдёт в решение по 1500
разделам форума — брифинг команды прямо предупреждает, что здесь ошибка дороже.

**Важная оговорка**: контракт зеркала §3 перечисляет ровно 4 запрещённых класса
(закрытый список, как и виды сносок — Global Constraint №2), и «немой пост форума» в
этот список НЕ входит. Формально исполнитель реализовал ровно то, что описывает
контракт, — не изобрёл новый класс сам, что тоже правильно (см. Global Constraint №2 по
аналогии). Поэтому это не дефект кода задачи 7, а вопрос политики: считать ли контракт
неполным и добавлять ли форуму симметричный класс «из одних картинок либо мусорного
текста». Оставляю решение лиду, а не переделываю.

**Как воспроизвести:**
```python
import sqlite3
from pipeline import notes
conn = sqlite3.connect("data/forum.sqlite")
tids = [tid for tid, in conn.execute(
    "SELECT t.tid FROM threads t WHERE EXISTS (SELECT 1 FROM posts p WHERE p.tid=t.tid)")]
mute = []
for tid in tids:
    posts = conn.execute("SELECT markdown FROM posts WHERE tid=?", (tid,)).fetchall()
    best = max((len(notes.normalize_spaces(notes.citable(md or "")).strip()) for (md,) in posts), default=0)
    if best < 8:
        mute.append(tid)
print(len(mute))  # -> 23
```

### 2 [Низкая, документация] `citable_sources()`/отчёт неверно приписывают исключение пустых тем форума функции `notes.citable_source`

И докстринг `coverage.citable_sources` (строки 176–179 `pipeline/coverage.py`), и
`task-7-report.md` («Три класса контракта... — те же три, что различает
`notes.citable_source`... пустые темы форума...») утверждают, что `notes.citable_source`
различает ТРИ класса, включая пустые темы форума. Это фактически неверно: сама функция
`notes.citable_source` проверяет регэкспами только `FAQ` и `Блог` (`_CITABLE_FAQ`,
`_CITABLE_BLOG`); имя вида «Тема N» не матчит ни один паттерн и падает в
`return True, ""` — то есть **говорит «цитируемо» для ЛЮБОЙ пустой темы**. Собственный
докстринг `notes.py` (строки 182–189) это прямо документирует и объясняет: третья ветка
не заведена НАРОЧНО, потому что у пустой темы нет ни одного заголовка `##### Пост <MID>`
вовсе — `notes.section()` вернёт `None` раньше, чем вопрос о цитируемости источника
вообще возникнет, то есть защита структурная (через отсутствие якоря в `facts.check_one`),
а не через `citable_source`.

Проверил эмпирически:
```python
from pipeline import coverage, notes
import sqlite3
conn = sqlite3.connect("data/forum.sqlite")
for tid in [tid for tid, in conn.execute(
    "SELECT tid FROM threads t WHERE NOT EXISTS (SELECT 1 FROM posts p WHERE p.tid=t.tid)")][:5]:
    print(notes.citable_source("Тема %d" % tid, conn))
# -> (True, '') для всех — citable_source НЕ отвергает пустые темы
```

Практических последствий нет: списки `citable_sources()` (охват) и фактическая
«запрещённость публикации» СОВПАДАЮТ по итогу — я прогнал все 591 FAQ/блог-имени из
`citable_sources()` через `notes.citable_source()` (0 расхождений), плюс отдельно все
17 дублей FAQ и все 56 выдержек блогов дают `citable=False` через `citable_source`
(17/17, 56/56) — а пустая тема, даже получив `citable=True` от `citable_source`,
физически не может пройти `facts.check_one` (нет якоря `#Пост N`). Это ровно тот
случай из п.3 брифа («если разойдутся, охват по одному правилу, публикация по
другому») — я специально проверил и подтверждаю: **на сегодня не расходятся**, но
объяснение МЕХАНИЗМА в докстринге/отчёте неверное. Рекомендация: поправить
формулировку в докстринге `citable_sources` и в отчёте (не «citable_source различает
пустые темы», а «пустые темы исключены отдельным условием `EXISTS posts`, потому что
`citable_source` их не проверяет — этот класс закрыт структурно через отсутствие
якоря, см. докстринг `notes.py`»). Правки кода не требует.
