# Три уточнения

## R1 — правило по стороне САМОСТОЯТЕЛЬНОЕ. Проверено мутацией

`looks_like_placeholder` смотрит только на `min(size) <= PLACEHOLDER_MAX_SIDE`
(=2): ни байтов, ни хэша в правиле нет. Подтвердил синтетикой в копии:

| тело | image_size | правило класса | приговор по хэшу | итог |
|---|---|---|---|---|
| PNG-трекер 1×1, **985 байт** (не 43), хэш неизвестен | (1, 1) | **True** | None | **заглушка** |
| JPEG 2×900 (полоска) | (2, 900) | True | None | заглушка |
| PNG 3×3 (граница) | (3, 3) | False | None | **не заглушка** |
| мусор (формат не опознан) | None | False | — | **не заглушка** |
| PDF | — | False | — | не заглушка |

То есть другой трекер, который принесёт добор Ф3, ловится правилом, а не
хэшем. Граница 3 px и трактовка «не знаю → не заглушка» — в нужную сторону:
пометить содержимое утраченным по незнанию хуже, чем пропустить заглушку.

## R2 — байт-идентичность НЕ автоматическая. Настоящая фотография уцелевает

Автоматического правила «≥3 адресов → заглушка» в коде нет; есть
`DECIDED_PLACEHOLDER_SHA256` — **один** приговор, sha256 плюс основание
словами («баннер VFL.RU „изображение было удалено“»). Проверил своей
мутацией: JPEG 640×360 (ровно тот случай, что ты нашёл снизу на двух шардах
radikal.ru) → `is_placeholder` **False**, в приговорах отсутствует.
`sieve_report` такие группы только перечисляет.

Проверил не приговор, а его исполнение. Взял файлы на диске, у которых в

| фикстура | `is_image` | `image_size` | `is_placeholder` |
|---|---|---|---|
| старая (`сигнатура + нули`) | True | **(0, 0)** | **True** |

То есть находка настоящая: старая фикстура изображала то, чего в корпусе не

не ослаб, а окреп: раньше он проверял «валидная сигнатура», теперь
