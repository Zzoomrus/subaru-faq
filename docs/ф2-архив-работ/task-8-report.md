## Пункт 1: позиционные картинки форума — файлы внутрь вики

Проблема на входе: заметки форума ссылались на картинки вида
`![[gadanie.fun/3b0c0a4497aa1ce0.jpg]]`, но сами файлы лежали в
`data/assets/files/` — вне вики и вне git (`data/` целиком в `.gitignore`).
Проверка целостности (`pipeline/check_mirror.py`) на старте задачи дала
**1525 битых вставок**.

Решение — тот же приём, что уже применён у `mirror_faq.py`/`mirror_blog.py`
в задачах 6–7: копировать РЕАЛЬНО ИСПОЛЬЗОВАННЫЙ файл в `<out_dir>/assets/`
и вставлять относительный путь, а не сырой путь из базы.

- `pipeline/mirror.py`: `write_all`/`render_thread` получили параметры
  `assets_root`/`dest_dir`. Когда оба заданы (так их передаёт `write_all`),
  новая функция `_copy_forum_asset` копирует файл из
  `data/assets/files/<local_path>` в `wiki/Источники/assets/<basename>` (имя
  без хоста безопасно — `basename` уже равен `<hash16><ext>`, а хэш взят от
  ПОЛНОГО URL в `fetch_assets.local_name`, значит уникален и без хоста) и в
  заметку идёт `assets/<basename>`. Файл в базе указан, а физически на диске
  отсутствует (расхождение манифеста добора и содержимого
  `data/assets/files/`) → та же честная пометка об утрате, что и при
  `local_path IS NULL` — глобальное ограничение фазы «ни одной битой
  вставки» соблюдено и в этом крайнем случае. Без `assets_root`/`dest_dir`
  (юнит-тесты, которым копирование не нужно) поведение прежнее — сырой
  `local_path` как есть, обратная совместимость с существующими тестами
  сохранена без правок.
- `pipeline/run.py`: обнаружился отдельный пробел, не входивший в
  формулировку пункта 1, но напрямую угрожавший главной гарантии фазы —
  `assets_state.sync_to_db` вызывался только из подкоманды `assets`. Значит
  `ingest --rebuild`/`all --rebuild` пересоздавали бы `attachments` со
  сплошным `local_path = NULL`, зеркало отрендерило бы все 1484 картинки
  пометками об утрате, а проверка целостности всё равно дала бы «четыре
  нуля» — потому что вставок не было бы вовсе, а не потому что они верны.
  Добавил вызов `assets_state.sync_to_db` сразу после загрузки
  форума/FAQ/блогов внутри `ingest`/`all`, и прокинул `--assets-root` в
  `mirror.write_all` для `mirror`/`all`.
- `docs/ф0-ф1-отчёт.md`: добавлена пометка «Обновление (Ф2, задача 8):
  позиционные картинки сделаны» в раздел «Что в архиве отсутствует и
  почему» (бриф явно просил эту правку).
- Тесты: 4 новых в `tests/test_mirror.py` (копирование+вставка, деградация
  в пометку при отсутствии файла на диске, дедуп копии при повторном
  использовании файла в двух темах, юнит-режим без `dest_dir` не трогает
  `local_path`); `tests/test_run.py._args` теперь явно передаёт
  `--assets-manifest`/`--assets-root` во временный каталог — без этого
  `ingest`/`all` в тестах подхватили бы боевой `data/assets/` по дефолтному
  относительному пути.

Результат: перегенерировал зеркало, проверка целостности —
**0/0/0/0** (было 1525). 255 тестов зелёных (было 251). Коммит `da67e37b`.

## Пункт 2: замер дублирования между разделами

Первый замер (по имени скопированного файла и по точной строке `url` в
базе) дал «пересечений нет» между `Источники/assets`, `FAQ/assets`,
`Блоги/assets`. **Ревью лида нашло, что это ложный ноль** — метод сравнения
не мог поймать дублирование по другой причине, см. ниже.

Пересчитал **по содержимому файла** (`sha256` байт, а не имя/URL):

| Пара | Файлов | Объём |
|---|---:|---:|
| форум ∩ FAQ | 0 | 0 |
| форум ∩ блоги | 0 | 0 |
| FAQ ∩ блоги | **105** (все файлы FAQ) | **7,49 МиБ** |

Причина — не смысловая (не общий пул фото форума и блогов), а механическая:
`mirror_faq._local_asset_name`/`fetch_assets.local_name` считают имя файла
в вики от **полного URL, включая схему и хост**, а сопоставление с архивом
Ф0/Ф1 (`mirror_faq._normalize_asset_path`, через `urlsplit(url).path`) хост
и схему уже игнорирует. Итог: код сам знает, что
`http://subaru-faq.ru/upload/…` и `https://www.subaru-faq.ru/upload/…` —
один файл на диске архива, но при копировании в вики кладёт его дважды под
двумя разными именами — по разу для FAQ и для блогов, каждый раз через URL
с отличающимся хостом/схемой. Отсюда точное совпадение 1:1 — 105 из 105.

По решению лида **дедупликация не сделана** в этой задаче: 7,5 МиБ на вики
в 278 МиБ — не повод переименовывать файлы и перегенерировать затронутые
заметки вне плана. Записано в открытые вопросы `docs/ф2-отчёт.md`: имя файла
стоит считать от нормализованного пути (без хоста/схемы), сделать это одним
заходом вместе со следующей перегенерацией разделов FAQ/блогов.

Заодно лид попросил проверить недостачу картинок FAQ/блогов (231 и 392 URL
против 105 и 270 найденных в архиве Ф0/Ф1 — разница 126 и 122, 248 всего) —
пересчитал тем же вопросом («не спрятался ли `www.` где-то ещё») и
подтвердил: **248 не изменилось**. Определение «есть ли файл в архиве» уже
шло по нормализованному пути (та же `_normalize_asset_path`, что и у
находки про дублирование выше) — в отличие от копирования уже найденных
файлов (отдельный шаг, где и была ошибка), здесь host/схема с самого начала
не участвовали в сравнении. Перепроверил отдельно: пересечение недостающих
путей FAQ/блогов — 0, несостыковок «недостающий в одном разделе = найденный
в другом» — 0, совпадений по регистру сверх точных — 0. Из 248: 135 —
собственные снимки сайта вне `upload/blog/…` (`www.subaru-faq.ru/cars/*.jpg`,
архив Ф0/Ф1 такие пути не собирал), 113 — внешние фотохостинги.

Также обнаружил (не просили дедуплицировать, но важно для планирования):
`faq_images`/`blog_images` не имеют колонки статуса добора, в отличие от
форумных `attachments` (`kind`/`status`) — `local_path` у них всегда `NULL`,
`mirror_faq`/`mirror_blog` резолвят путь только временно, при генерации
заметки, никогда не пишут обратно в базу. Записано в открытые вопросы.

## Пункт 3: перекачка 10 антибот-страниц

Список — `docs/coverage-notes.md`, раздел «Антибот-заглушки в message_\*»:
10 файлов `message_*.html`, у каждого сохранён маркер антибот-проверки
(`ctSetCookie`/`ctMouseData`) вместо контента форума. URL восстановил из
`data/raw/archive/manifest.jsonl` по имени файла (ключ `message|fid|tid|mid`).

Прогон на VPS `bots` (сеть Wayback — только оттуда, см.
`global-constraints.md`): для каждого из 10 точных URL запросил ПОЛНЫЙ
список снимков `fetcher.cdx_snapshots` (не только уже известную плохую
метку). Результат: **у всех десяти в CDX ровно один снимок, и это тот же
известный плохой**. Дополнительно (сверх брифа, для полноты) проверил
альтернативную форму адреса той же темы (`PAGE_NAME=read` вместо
`PAGE_NAME=message`, три варианта хоста на тему) — снимков не нашлось ни у
одной из 10.

Итог: **0 из 10 восстановлено** — не «не нашли», а надёжно установленный
факт: Wayback архивировал каждую из этих страниц форума ровно один раз в
жизни, и именно в момент, когда сайт отдал антибот-проверку вместо
контента. Разбор по подгруппам (что теряется реально) — в
`docs/ф2-отчёт.md`, раздел «Чего не достали и почему».

## Пункт 4: полный прогон с нуля

Главная проверка фазы: восстанавливается ли состояние добора из манифеста +
файлов на диске при полной пересборке базы, а не теряется молча.

Снял цифры «до», снёс `data/forum.sqlite`, прогнал
`python -m pipeline.run all --rebuild` (~100 с) прямо в рабочей копии (git
был чист, кроме незакоммиченного локального `wiki/.obsidian/` — не
относится к задаче), затем `mirror`, `check`.

| Критерий | До | После |
|---|---:|---:|
| целостность (broken_links/anchors/dup/embeds) | 0/0/0/0 | 0/0/0/0 |
| вставок `![[assets/…` во всей вики | 1925 | 1925 |
| файлов в каталогах `assets/` (форум+FAQ+блоги) | 1859 | 1859 |
| `attachments.local_path` непустой в базе | 1856 | 1856 |
| пометок «изображение не сохранилось» | 6267 | 6267 |

Все пять цифр совпали ровно. Плюс — `git status` после пересборки: **0
изменённых файлов**, т.е. зеркало воспроизвелось байт-в-байт, не только по
счётчикам. Покрытие (`ok`/`short`/`extra`/`missing`/`unverifiable` =
1430/392/75/2829/1612) и `posts`/`threads` в базе (48689/6338) тоже совпали
с цифрами `docs/ф0-ф1-отчёт.md`/`coverage-notes.md`. Тесты — 255 зелёных
после пересборки. Коммитить было нечего (diff пуст).

## Сомнения / открытые вопросы

- **Дедупликация FAQ↔блоги не сделана.** Осознанно, по решению лида (см.
  пункт 2) — 105 файлов / 7,49 МиБ, откладывается до следующей
  перегенерации этих разделов.
- **У `faq_images`/`blog_images` нет статуса добора** — колонка
  `local_path` есть, но всегда `NULL`; будущему добору 248 недостающих
  картинок этих разделов нужен отдельный пересчёт «URL минус индекс
  `manifest-assets.jsonl`» или отдельная колонка статуса по аналогии с
  `attachments.kind`/`status`.
- **10 антибот-страниц потеряны навсегда** — проверено исчерпывающе (все
  снимки точного URL + альтернативная форма адреса), решения на уровне
  добора нет.
- **Если вики пойдёт в публикацию** — картинки стоит вынести из истории
  git до этого (сейчас чистый клон тянет 248 МиБ истории только из-за
  бинарников).

Замер дублирования (пункт 2):
```bash
.venv/bin/python -c "
import hashlib
from pathlib import Path
def sha256(p): return hashlib.sha256(p.read_bytes()).hexdigest()
dirs = {'форум': Path('wiki/Источники/assets'), 'faq': Path('wiki/Источники/FAQ/assets'),
        'блоги': Path('wiki/Источники/Блоги/assets')}
h = {n: {sha256(f) for f in d.glob('*')} for n, d in dirs.items()}
print('faq ∩ блоги:', len(h['faq'] & h['блоги']))
"
```
