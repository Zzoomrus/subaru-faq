# Архив форума subaru-faq.ru из Wayback Machine

Сайт мёртв: домен на парковке Ru-Center (зона переписана 25.07.2023), последний живой
снимок — 25.09.2022. Единственный источник — Wayback Machine.

## Что качаем

| | |
|---|---|
| Страниц в списке | **5 938** |
| Тем форума | **3 519** (все 24 раздела) |
| Ожидаемый объём | **~300 МБ** сырого HTML (~50 МБ в `tar.zst`) |
| Кодировка страниц | windows-1251 |

Состав списка: `read` — 3 406 страниц тем с пагинацией, `message` — 2 296 страниц
(это темы, у которых в архиве **нет** ни одного `read`-снимка; 1 204 темы существуют
только так), `list` — 235 страниц-оглавлений разделов (нужны как опись: по ним потом
сверяется, какие темы были и какие удалось достать), `index` — корень форума.

## Главная сложность: Wayback троттлит

Архив отдаёт снимки вероятностно: ~5 из 6 запросов возвращают `503` (ровно через ~5,9 с —
это сознательный лимитер, не перегрузка). Проверено и исключено:

- **не наш IP** — с VPS вне туннеля картина та же, что с мака;
- **не битые снимки** — один и тот же URL при повторе даёт то 200, то 503;
- **не режим** — `id_`, обычный и `if_` троттлятся одинаково;
- CDX-API и `archive.org` при этом отвечают нормально — режется именно отдача снимков.

Замер на реальном прогоне (772 страницы за 5,7 ч) показал механику **token bucket**:

- первые 35 минут — накопленный запас: 120+ страниц каждые 10 минут, отдача 100%;
- дальше плато на скорости пополнения: ~1,1 стр/мин, успехи приходят **пачками** по
  2–12 штук примерно раз в 110 с (автокорреляция даёт слабые пики на 85–135 с и кратных).

Отсюда режим работы скрипта:

- **холодный** — по одному запросу с паузой 2,5–12 с (по текущей отдаче): попытки в
  пустой фазе бесполезны, жечь их незачем;
- **горячий** — сразу после успеха идёт залп из `BURST` (по умолчанию 4) параллельных
  запросов с паузой 0,6 с, чтобы выбрать пачку целиком, пока окно открыто;
- 120 отказов подряд → пауза 5 минут.

Ожидание по времени: на скорости пополнения это **до нескольких суток** на одном клиенте;
щедрое окно (как в первые 35 минут) выгребает сотни страниц за минуты. Цикл переживает
и то, и другое без присмотра.

## Запуск

На VPS (процесс переживает выключение компа — `nohup`):

```bash
ssh bots 'cd /root/subaru-faq/scratch && DEST=/root/subaru-faq/archive nohup python3 fetch.py > /root/subaru-faq/fetch.log 2>&1 &'
```

Прогресс:

```bash
ssh bots 'tail -5 /root/subaru-faq/fetch.log; ls /root/subaru-faq/archive/pages | wc -l'
```

Остановить (докачается при следующем запуске — ничего не теряется):

```bash
ssh bots 'pkill -f fetch.py'
```

### Вторым клиентом (если хочется быстрее)

Два независимых клиента примерно удваивают выхлоп. Список делится по индексу, файлы не
конфликтуют, но манифесты у каждого свои:

```bash
ssh bots 'cd /root/subaru-faq/scratch && DEST=/root/subaru-faq/archive SHARD=0/2 nohup python3 fetch.py > /root/subaru-faq/fetch-0.log 2>&1 &'
cd ~/Downloads/subaru-faq-archive/tools && SHARD=1/2 nohup python3 fetch.py > ~/Downloads/subaru-faq-archive/fetch-1.log 2>&1 &
```

При сборке результата просто склеить манифесты: `cat manifest*.jsonl > manifest.jsonl`.
Учти: мак ходит через туннель с общим выходным IP — базовая отдача там хуже, чем с VPS.

## Шаг 2: вложения со своего домена

Запускать **после** того, как закончится выкачка страниц (в логе появится «ИТОГ»).

```bash
ssh bots 'cd /root/subaru-faq/scratch && setsid nohup env DEST=/root/subaru-faq/archive python3 fetch_assets.py > /root/subaru-faq/assets.log 2>&1 < /dev/null & exit 0'
```

**1 087 файлов, ~61 МБ** — аватары, картинки постов, вложения блогов и статей. Кладутся
в `assets/` с сохранением исходных путей (`assets/upload/forum/avatar/…`). Список берётся
из индекса `tools/cdx-upload.txt.gz`, темп и докачка — как на шаге 1.

Внешние картинки (piccy, radikal и прочие фотохостинги — на форуме их много) сюда
**не входят**: их адреса живут в тексте постов, и разбираться с ними будем на этапе
приведения архива к удобному виду — тогда же и станет видно, что из них пережило.
Заготовка для сбора таких ссылок из HTML — `tools/extract_assets.py`.

## Забрать результат

```bash
ssh bots 'cd /root/subaru-faq && tar -I "zstd -19" -cf archive.tar.zst archive'
scp bots:/root/subaru-faq/archive.tar.zst ~/Downloads/
```

## Что лежит рядом

- `pages/` — сырой HTML, скачан через `id_`-модификатор: **без** тулбара Wayback и без
  переписанных ссылок, ровно то, что отдавал сайт. Имя файла = ключ страницы
  (`read_<FID>_<TID>_<стр>.html`, `message_<FID>_<TID>_<MID>.html`).
- `manifest.jsonl` — по строке на скачанную страницу: ключ, исходный URL, timestamp
  снимка, размер. Пишутся **только успехи**, поэтому повторный запуск честно добирает
  недостающее.
- `failures*.json` — что не удалось закрыть за прогон (с числом попыток).
- `tools/fetch-list.json` — план выкачки: для каждой страницы до трёх снимков-кандидатов
  (свежий + самые полные), перебираются по кругу.
- `tools/cdx-forum-full.txt.gz` — исходный индекс: 61 893 снимка страниц форума.
- `tools/build_list.py` — сборка плана из индекса (канонизация URL, дедуп, отсев
  служебных страниц: логин, регистрация, `print=Y`, поиск, профили).
- `tools/cdx_fetch.sh` — сбор индекса из CDX по годам (целиком архив отдаёт 504).

## Разбор (потом, локально)

Страницы в windows-1251, вёрстка — Битрикс-форум (`template2`). Что учесть:

- один и тот же пост может встретиться и в `read`-, и в `message`-странице — дедуп по
  `MID`;
- длинные темы разбиты на страницы (`PAGEN_1`), собирать по возрастанию;
- `list`-страницы дают полный перечень тем раздела — по ним считается покрытие
  (сколько тем было против скольких достали).
