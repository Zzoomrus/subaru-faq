# Долги и находки Ф2, которые обязаны попасть в план Ф3

Собрано из решений журнала и отчётов волны правок. Каждый пункт — с причиной, чтобы при
планировании не пришлось поднимать переписку.

## Работы

1. ~~**Дедуп FAQ** (Ruling 35).~~ **Сделано, задача 1 Ф3** (`pipeline/faq_dedup.py`,
   `faq.duplicate_of_engine`/`duplicate_of_nr`). Числа журнала (16 вопросов, 14 из 20 дословно, ~154
   уникальных) были оценкой при неявной нормализации — измеренное правило (вопрос: только
   буквы+цифры, регистр вниз; вхождение ответа: точная подстрока после схлопывания пробелов

   вхождению ответа — `FAQ старый 114`/`155`) → **157** уникальных записей из 174. Первая прогонка
   без схлопывания пробелов дала 15/0/159 и это прошло мимо ревью первой сдачи — два движка форума
   разбивают абзацы по-разному, точное посимвольное сравнение эти два случая пропускало. Дубль не
   удалён (данные Ф2 не разрешала трогать), только помечен — в базе указателем, в заметке
   фронтматтером `дубль_чего` и коллаутом `[!warning] Дубль`.
2. ~~**Покрытие FAQ и блогов** (Ruling 36).~~ **Сделано, задача 7 Ф3**
   (`pipeline/coverage.faq_blog_coverage`, `citable_sources`, `citation_coverage`).
   `report`/`summary` по-прежнему считают только форум (у темы есть "ожидание" из
   оглавления для сверки, у FAQ/блога — нет) — вместо сверки простой подсчёт по
   четырём непересекающимся группам. Замер на боевых данных (21.08.2026,
   `data/forum.sqlite`): FAQ 174 = 17 дублей + 24 из одних картинок + 6 пустых ответов
   + 127 с текстом; блоги 528 = 56 выдержек + 8 из одних картинок + 464 с текстом.
   Плюс замер спеки §10 «доля источников, не процитированных ни разу»: знаменатель —
   3509 тем форума с постами + 127 FAQ с текстом + 464 блога с текстом = **4100**
   цитируемых источников корпуса (дубли FAQ, выдержки блогов, пустые темы форума и
   33 записи из одних картинок — не в знаменателе: последние физически нечем
   процитировать, это не упущение ИИ, и `faq_blog_coverage`/`citable_sources` считают
   их отдельно, не размывая долю). На пилоте из одной готовой статьи («Расшифровка
   VIN Subaru») процитирован 1 источник из 4100 — доля непроцитированных 0,9998, и
   это ожидаемое число на пилоте из одной статьи, а не дефект: команда `coverage`
   измеряет охват, он вырастет по мере сборки статей задачи 8.

## Что знать до написания первой статьи

- **Канон дословной проверки — тело заметки**, не поле базы (Ruling 30). Расхождение у 27267 постов
  из 48689, у 88 записей FAQ из 174, у 492 блогов из 528. Порядок: искать по FTS → ссылаться по
  якорю → сверять `grep -F` по телу заметки. Полностью — `docs/контракт-зеркала.md`.
- **6341 пометка «(изображение не сохранилось: …)»** — текст генератора, не автора. Проверка цитаты
  на таком тексте «пройдёт» и подтвердит то, чего человек не писал.
- **Просеяно НЕ МЕНЕЕ 75 заглушек хостингов** (Ruling 45/46), «возвращено» 1409 из 6600 — 21,3%, и
  это ПОЛ, а не потолок: одиночную заглушку по одному адресу просев не видит. Картинку, на которую
  опирается утверждение статьи, стоит открыть глазами; новые группы печатает `run assets sieve`,
  приговор конкретным байтам выносит человек (`attachments.DECIDED_PLACEHOLDER_SHA256`).
- **2829 тем из 6338 пусты** — ссылаться можно на 3509.
- **56 выдержек блогов из 528** — свидетельство «запись была», но не дословный источник;
  комментариев у них нет вовсе (728 комментариев принадлежат 113 записям).
- **33 записи состоят из одних картинок** (25 FAQ + 8 блогов): текста нет, поиск не найдёт никогда,
  цитировать нечего — ссылаться «здесь фотографии того-то» можно.
- **«Повторный прогон ничего не нашёл» — не факт об архиве**, а следствие терминальных статусов.
- **Ruling 34 в журнале ОТМЕНЁН**, читать Ruling 39: ключ имени файла включает строку запроса.

## Уроки процесса, стоившие дороже всего

- Зелёные тесты и четыре нуля целостности НЕ отличают «все вставки настоящие» от «вставки стоят не
  там»: +1316 ложных вставок в 49 заметках прошли и то, и другое. Поймала только сверка числа
  вставок до/после. Считать штуки при каждой правке генератора.
- Тест, красный из-за отсутствия функции, — не доказательство, что он видит дефект. Доказывать
  через `git stash` на ГОТОВОМ коде.
- Обоснование правки, пришедшее от того, кто её писал, проверять отдельной рукой, если правка
  способна испортить данные молча.
